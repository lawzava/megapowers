# Learning loop

Use this procedure to observe, propose, prove, promote and retire lessons.
Use normal transcript, file and Git tools. Never edit instructions, memory or
checks without user approval of that change. Without local evidence, record
candidates in the reply and promote nothing without reading back the target.

## 1. Observe

Build a scoped scorecard from local Claude Code and Codex transcripts and
project run journals using [session mining](session-mining.md). Report source
counts and date window before comparisons. Record corrections, skill loads,
corrections after loads, historical gate blocks, verification reports,
foreground sleeps and run outcomes. Read the sessions behind each number.
A correction after a load does not show the skill caused it. Sparse keyword
matches cannot establish an absence of problems.

## 2. Propose

Run a [retrospective](retrospective.md). For each repeated class, choose a
check when deterministic tooling can catch it, instructions for project
judgment, native memory for cross-project preferences, or an upstream proposal
when Megapowers itself caused the issue. Audit memory with
[memory hygiene](memory-hygiene.md).

Record each candidate's ID, class, lesson, surface, target, evidence type,
and timestamped sources. Distinguish direct-statement, direct-observation,
source-backed and history-entry-only evidence. Keep lesson records outside the
repository and implementer context. Use an approved private writable location.

## 3. Prove

A check lesson must fail on the actual historical mistake and pass now.
Use a temporary detached worktree at the failing commit. Supply newly added
check material there so it tests the mistake rather than missing tooling.
Never replace historical code under test or write through symlinks.
For instructions, memory or upstream lessons, compare the same cases with and
without the change. Record evidence and limits. A passing historical check or
failing current check does not prove the lesson.

## 4. Promote

Write only the approved change. Require a proof or at least two sources.
Rerun a check lesson's command and read the exact instruction or memory anchor
from its target. Missing read-back blocks promotion. Remove prose made
redundant by an enforcing check.

## 5. Review and retire

Review monthly when scheduled, or on request, using a project-specific date
window. A recurrence after promotion means recurring. Quiet beyond the recorded
age limit (default 90 days) means stale. Quiet within it means holding.
A window starting before promotion or lacking signal means unknown.
Unpromoted candidates past their age limit are expired. Bring recurring, stale,
expired or unknown lessons to the user. Retire only with agreement and record
why. Never infer success from missing evidence.

## Upstream

Show the user sanitized scorecards and lesson exports before sharing under
safe-effects. Remove project paths, sources, commit IDs and path-bearing check
arguments. Omit free-text lessons unless reviewed; client names may evade
redaction. Keep only well-formed Megapowers skill names. A proposed installed-ab
case needs oracleProofs and a comparison showing no regression before adoption.
