# Terminology

When you or the user use loose, overloaded, or conflicting names for a concept
a decision depends on, settle the name as a decision of its own, before the
decisions that use it.

Check each candidate against the terms the project already uses in code, docs,
and any glossary. Test it in a few concrete sentences about the system; a name
that needs a qualifier in every sentence is the wrong name. Prefer the word the
user actually says over a technically tidier one.

The interview authorizes no change. Propose glossary or decision-record
entries in the summary; do not write them.
